Reading an answer sheet from a phone camera.

01

The problem

A student fills in a paper optical form. They photograph it with a phone, or a school scans a stack of them into a PDF. The system has to read two things off that image — who the sheet belongs to, and what they answered — and turn it into a score.

A purpose-built OMR scanner solves this by removing the hard part: controlled light, a fixed transport, a sheet that cannot be rotated. A phone gives you none of that. It gives you glare across half the page, a sheet at an angle, a sheet upside down, shadows from the hand holding it, and a resolution that varies with how close the student stood.

The bar was not "does it mostly work". The bar was the output of the machine it was replacing, on the same sheets.

02

Why it was hard

Every individual step has a textbook answer. Thresholding turns a photo into black and white. Hough circles find the bubbles. The difficulty is that each textbook answer has a parameter, and no single value of that parameter survives the range of photographs real students send.

A threshold that reads a bubble correctly in flat light merges two bubbles under glare. A radius that finds every circle on a close photograph finds printed decorations on a distant one. Tune for one page and you lose another.

So the pipeline does not try to pick the right parameter. It runs many, and treats each one as a witness.

03

The approach: gather evidence, then decide

Circles are detected under sixteen thresholding strategies in parallel. Each produces its own set of candidate circles. They are merged by majority vote, and the radii trimmed to the agreed range — a circle that only one strategy saw is noise; a circle fourteen of them saw is a bubble.

The surviving circles are then assembled into a graph: neighbours by distance and alignment, which yields the columns and rows of the form without anyone having told the system what the form looks like. A reader walks that graph and turns it into answers.

Stack NestJS and TypeScript in strict mode, PostgreSQL through Prisma, BullMQ and Redis for the queues. Image work in OpenCV and sharp, with scanned PDFs rasterised at 200 DPI. A small model reads rows, trained in PyTorch and exported to ONNX so it runs inside the backend rather than behind a second service to deploy and keep alive.

04

Orientation: rank the evidence

A sheet arrives in an unknown orientation, and getting it wrong means reading every answer in the wrong place. Rather than guess from the image, the system ranks what it can prove about identity:

  1. 3 An ID that passes its checksum and matches a student on the school's roll.
  2. 2 An ID that passes its checksum, matching nobody on file.
  3. 1 A name that matches.
  4. 0 Nothing legible.

Above that sits a second source: layout consensus across the upload. A single page cannot tell you much, but a batch of a hundred from the same form can. The mean offset between the digit block and the letter block, measured across every page, describes that form's shape — and any page whose offset is inverted is upside down, including the pages that carry no identity evidence of their own.

One page is a guess. A hundred pages of the same form is a measurement.

05

A feature removed because the number said so

The answer reader originally tried a 180° rotation when a first pass looked poor. It is an obvious thing to do, and it was wrong.

An upside-down read of an answer grid comes back looking formally valid — the right number of rows, one mark per row, nothing to flag — while being entirely fabricated. And because it looks valid, it gets saved.

So it was removed, and the problem solved with information the camera path already had: the student is signed in. We know whose sheet it should be before we read a single bubble. The half-turn is attempted on the identity field alone, and accepted only if it names that same student.

When it does, the student is asked to retake the photo the right way up — rather than being told, by a system that cannot actually tell, that they photographed somebody else's paper.

A rotation that produces a plausible wrong answer is worse than one that produces no answer. Only the identity field is safe to rotate, because it is the only field that can disprove itself.

06

Finding the booklet box nobody labelled

Exams ship in variants — booklet A, booklet B — with the same questions in a different order. Grade a sheet against the wrong key and every answer is wrong. The original approach inferred the variant from the answers: score the sheet against every key, take the highest net, and send ties to a human.

The sheet states its variant in a small box. The difficulty is that one page cannot tell that box apart from any other printed pair of circles — and there are many.

A hundred pages can, because of one thing that separates the booklet box from every decorative pair on the form: people mark it. So the system nominates the pair of circles in which exactly one circle is filled on the greatest number of pages — and then projects that position back onto each page's own detected circles, because a scanner shifts a sheet by more than the width of a bubble.

The box does not override the answers. 120 questions is a stronger measurement than one box, so the answers stay the judge; the box decides ties only. When the two disagree, the sheet is flagged for a reviewer rather than silently regraded. And it costs nothing to compute: the reader already hands over every circle it found.

07

The measurement

Booklet detection, scored against the commercial scanner's own output on the same 88 pages:

Correct86
Wrong0
Refused2

The two refusals were boxes the students had left blank. There was nothing to read, and the system said so instead of inventing an answer — which is the behaviour you want from it.

Zero wrong matters more than 86 right. A system that refuses when it cannot see is one a school can trust; a system that guesses is one that has to be checked, which is the job it was bought to remove.

08

What I got wrong

Both of these were caught before delivery. Both were measurement errors, not code errors.

A number that seemed to refute the design

The first run of booklet detection returned 58 correct, 35 wrong. The obvious reading was that students mis-mark the box about 36% of the time, and that reading the box was therefore a bad idea.

It was an alignment bug in the evaluation. Page number is not row number in the ground-truth file: the numbering drifts every time a page is skipped for not matching. Against the correct mapping, the same run was 86 correct, 0 wrong.

Before you accept a number that refutes your design, check that you are comparing the right rows. A result that convenient to misread deserves a second look at the harness, not just the hypothesis.

Frequency is not evidence

The first version of booklet detection nominated the most frequent pair of circles. It confidently picked a printed decoration that appears on every page and that nobody ever marks — and refused all 88 sheets.

Repetition is not a signal. Use is. The thing that distinguishes a form field from an ornament is that a human reaches for it.

09

How the work was run

  • Every threshold and design decision is backed by a number measured on real sheets, compared against the golden reference — the commercial device's own output.
  • Changes go through an issue, then a separate pull request, then CI running a matrix of accuracy tests for the reader. main is protected.
  • Decisions are written down in an architecture decision log — including the rejected ones, with their measurements, so nobody spends a week rediscovering that the half-turn retry costs 1.6 points.

Note on privacy No student names, identity numbers or sheet images appear in this write-up or in any of the figures. Every diagram here is drawn, not captured.
